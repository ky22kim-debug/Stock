# ETF 계좌 통합 관리 (PWA)

여러 계좌(기본 DC / 퇴직연금112 / 개인연금113, **자유롭게 추가·삭제 가능**)의 ETF 매매·손절계획·
일별 잔고(ETF 평가금액 + 예수금)·투자일지를 기록하는 단일 HTML 앱입니다. 서버·Streamlit·DB 없이
브라우저(로컬 저장소 + 선택적 Firebase 클라우드 동기화)만으로 동작합니다.

## 파일 구성

- `index.html` — 앱 본체 (UI + 로직, 전체 기능이 이 파일 하나에 들어있음)
- `manifest.json` — PWA 설치 정보 (아이콘, 앱 이름, 다크 테마)
- `sw.js` — 오프라인 캐싱용 서비스워커
- `icons/` — 앱 아이콘 (192/512, 일반 + maskable)
- `gen_icons.py` — 아이콘 생성 스크립트 (재생성할 때만 필요)

## 1) 가장 간단한 사용법 — 그냥 파일 열기

`index.html`을 더블클릭해서 PC 브라우저(Chrome/Edge)로 열면 바로 사용 가능합니다.
안드로이드는 이 폴더를 휴대폰에 복사한 뒤 Chrome에서 `index.html`을 열면 됩니다.
단, 이 방식(`file://`)은 홈 화면 설치·오프라인 캐싱은 지원되지 않고, 매번 브라우저로 열어야 합니다.

## 2) 안드로이드 앱처럼 설치하기 (PWA)

PWA 설치(홈 화면 아이콘, 오프라인 실행)는 브라우저 보안 정책상 `https://` 또는 `localhost`로
서빙되어야 활성화됩니다. 별도 서버를 운영할 필요 없이 **무료 정적 호스팅**으로 충분합니다.

**추천: GitHub Pages (무료, 서버 관리 불필요)**

1. GitHub에 새 저장소를 만들고 이 폴더(`etf_portfolio_pwa`) 내용을 그대로 업로드
2. 저장소 Settings → Pages → Branch를 `main`(또는 `master`) / `root`로 설정
3. 몇 분 뒤 `https://<사용자명>.github.io/<저장소명>/` 주소로 접속 가능
4. 안드로이드 Chrome에서 해당 주소 접속 → 메뉴 → "홈 화면에 추가" → 앱처럼 아이콘 생성, 오프라인 실행됨
5. PC Chrome/Edge에서도 주소창 오른쪽 설치 아이콘으로 데스크톱 앱처럼 설치 가능

GitHub 계정이 없거나 원치 않으면 Netlify/Vercel(드래그 앤 드롭 배포)도 동일하게 동작합니다.
로컬에서만 테스트하려면 이 폴더에서 `python -m http.server 8000` 후 `http://localhost:8000`으로
접속해도 설치·서비스워커가 동작합니다(테스트용, 컴퓨터를 꺼도 상관없는 배포는 아님).

## 3) 데이터는 어디에 저장되나요

기본적으로 브라우저의 `localStorage`에 기기별로 저장됩니다. 즉 PC와 안드로이드는 **자동으로
동기화되지 않습니다.** 두 기기를 같은 상태로 유지하려면 아래 두 방법 중 하나를 쓰세요.

- **Firebase 클라우드 동기화 (추천)** — 로그인한 기기끼리 실시간 자동 동기화, 무료. 아래 4번 참고.
- **구글 드라이브 수동 백업** — 파일을 내보내고 다른 기기에서 가져오는 수동 방식. 아래 5번 참고.
  Firebase를 설정하지 않았거나, 보조 백업 수단이 필요할 때 사용하세요.

## 4) 클라우드 동기화 설정 (Firebase, 무료·실시간)

설정하면 앱 **데이터 탭**에서 Google 계정으로 로그인만 하면 되고, 이후 한 기기에서 기록을 추가하면
다른 기기 화면에 자동으로 반영됩니다(수동 내보내기/가져오기 불필요). Firebase 무료 요금제(Spark)
범위 안에서 동작하며 신용카드 등록이 필요 없습니다.

**4-1. Firebase 프로젝트 만들기**

1. [console.firebase.google.com](https://console.firebase.google.com) 접속 → 사용하시는 구글 계정으로 로그인
2. **프로젝트 추가** → 이름 입력(예: `etf-portfolio`) → Google Analytics는 꺼도 무방 → 프로젝트 생성

**4-2. Firestore(데이터베이스) 켜기**

> ⚠️ 왼쪽 메뉴에는 **Realtime Database**라는 비슷한 이름의 다른 제품도 있습니다. 이 앱은
> **Firestore Database**를 사용하므로 반드시 그쪽에서 설정하세요. Realtime Database에 아래 규칙을
> 붙여넣으면 문법이 달라 "Parse error"가 납니다.

1. 왼쪽 메뉴 **빌드 → Firestore Database** → **데이터베이스 만들기**
2. 위치는 `asia-northeast3 (Seoul)` 선택 → **프로덕션 모드**로 시작(테스트 모드 아님) → 사용 설정
3. 만들어진 뒤 **규칙(Rules)** 탭으로 이동해서 기본 내용을 지우고 아래로 교체 → **게시**:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{uid} {
      allow read, write: if request.auth != null && request.auth.uid == uid;
    }
  }
}
```

이 규칙은 "로그인한 본인 계정(uid)의 문서만 본인이 읽고 쓸 수 있다"는 뜻입니다. 다른 사람이 이
앱 주소에 접속해 자기 구글 계정으로 로그인하더라도 각자의 빈 문서만 만들어질 뿐, 서로의 데이터는
볼 수 없습니다.

**4-3. Google 로그인 켜기**

1. 왼쪽 메뉴 **빌드 → Authentication** → **시작하기**
2. Sign-in method 탭에서 **Google** 선택 → 사용 설정 → 프로젝트 지원 이메일 선택(본인 이메일) → 저장

**4-4. 웹 앱 등록하고 설정값 받기**

1. 프로젝트 개요 페이지에서 `</>` (웹) 아이콘 클릭 → 앱 닉네임 입력(예: `etf-web`) → Firebase Hosting은
   체크 안 해도 됨 → 앱 등록
2. 화면에 `const firebaseConfig = { apiKey: "...", authDomain: "...", ... }` 형태의 코드가 표시됩니다.
   이 객체 전체를 복사하세요.

**4-5. index.html에 붙여넣기**

`index.html`에서 아래 부분을 찾아 위에서 복사한 값으로 통째로 교체합니다.

```js
const firebaseConfig={
  apiKey:"YOUR_API_KEY",
  authDomain:"YOUR_PROJECT.firebaseapp.com",
  projectId:"YOUR_PROJECT",
  storageBucket:"YOUR_PROJECT.appspot.com",
  messagingSenderId:"YOUR_SENDER_ID",
  appId:"YOUR_APP_ID"
};
```

저장 후 (2번 항목대로 GitHub Pages 등에 이미 올려뒀다면) 파일을 다시 업로드하세요. 이후 앱의
**데이터 탭**에 "🔐 Google로 로그인하고 동기화 시작" 버튼이 나타납니다. 각 기기에서 같은 구글
계정으로 로그인하면 실시간 동기화가 시작됩니다.

**4-6. 사용 방법 (설정 완료 후)**

평소에는 아무 버튼도 누를 필요가 없습니다.

- 기록을 저장할 때마다 자동으로 클라우드에 업로드됩니다.
- 로그인된 다른 기기는 앱을 열어두기만 하면 변경이 자동 반영되고, 새로 열어도 최신 데이터가
  자동으로 내려옵니다.
- 오프라인에서 입력한 내용은 로컬에 쌓였다가 연결되면 자동 동기화됩니다.

데이터 탭의 버튼들은 예외 상황용입니다.

| 버튼 | 용도 |
|---|---|
| ⬆ 지금 클라우드로 올리기 | 이 기기 데이터를 클라우드에 강제로 덮어쓰기 |
| ⬇ 클라우드에서 불러오기 | 클라우드 데이터를 이 기기에 강제로 내려받기 |
| 🔍 연결 진단 | 로그인·서버 읽기·서버 쓰기를 각각 테스트해 원인 표시 |

**참고**
- `firebaseConfig`의 `apiKey`는 비밀 값이 아닙니다(공개 저장소에 올라가도 안전하도록 설계됨).
  실제 보안은 4-2에서 설정한 Firestore 규칙(로그인한 본인만 접근)이 담당합니다.
- 동기화는 "문서 전체 덮어쓰기(마지막 저장이 이김)" 방식입니다. 두 기기에서 동시에 서로 다른
  기록을 입력하면 나중에 반영된 쪽만 남습니다.
- 자주 만나는 오류: `permission-denied`(4-2의 규칙을 게시하지 않음), `auth/configuration-not-found`
  (4-3의 Google 로그인 미설정), `auth/unauthorized-domain`(Authentication → Settings → 승인된
  도메인에 앱 주소를 추가해야 함).
- 이미 로컬/드라이브 백업으로 기록이 쌓여 있는 기기에서 먼저 로그인하세요. 클라우드에 아직
  아무 기록이 없으면 그 기기의 현재 데이터가 그대로 클라우드의 시작 데이터가 되고, 이미 클라우드에
  데이터가 있는 상태에서 다른(비어 있는) 기기가 로그인하면 그 기기 화면은 클라우드 데이터로
  덮어써집니다.
- Firestore 문서 하나의 용량 한도(1MB)가 있어 수년간 방대한 일지를 남기는 극단적인 경우가 아니면
  문제되지 않습니다.

## 5) 구글 드라이브 수동 백업 (보조 수단)

Firebase를 설정하지 않았거나 별도 백업이 필요할 때 앱 안 **데이터 탭**에서 사용하세요.

1. 구글 드라이브에 전용 폴더 하나(예: `ETF관리백업`)를 만들어 둡니다.
2. 기록을 추가한 기기에서 **"⬇ 파일로 내보내기"**를 누르면 `etf관리_백업_YYYY-MM-DD.json` 파일이
   다운로드됩니다. 이 파일을 그 드라이브 폴더로 옮겨두세요(안드로이드는 드라이브 앱의
   업로드 기능 사용, PC는 다운로드 폴더를 드라이브 동기화 폴더로 지정해두면 자동으로 올라감).
3. 다른 기기에서 **"📂 파일 가져오기"**를 눌러 드라이브 폴더의 최신 백업 파일을 선택하면
   그 기기의 기록이 해당 백업 내용으로 교체됩니다.
4. 항상 **가장 최근에 내보낸 파일**을 가져와야 합니다. 두 기기에서 동시에 기록을 추가하고
   서로 다른 백업을 나중에 덮어쓰면 먼저 기록한 내용이 사라질 수 있으니, 기록은 가급적
   한 기기에서 몰아서 하고 다른 기기는 "가져오기"로 최신화하는 방식을 권장합니다.

텍스트로 복사/붙여넣기하는 백업(기존 방식)도 "데이터 탭 → 텍스트 백업/복원"에 그대로 남아있습니다.

## 6) 클로드 업로드용 분석 데이터

**"CSV 저장"** 버튼을 누르면 일별잔고 / 매매기록 / 투자일지가 한 파일(`ETF관리_YYYY-MM-DD.csv`)로
저장됩니다. 이 CSV를 클로드 대화에 그대로 업로드하면 수익률 추이, 계좌별 비중, 매매 판단
분석 등을 바로 요청할 수 있습니다.

## 7) 이 앱에서 추가/변경된 점 (원본 연금관리 html 대비)

- **예수금(현금) 입력 추가** — 계좌별로 ETF 평가금액과 별도로 예수금을 입력. 대시보드 총자산은
  ETF 평가금액 + 예수금 합계로 계산됩니다.
- **계좌 자유 추가/삭제** — 더 이상 DC/퇴직연금/개인연금 3개로 고정되지 않습니다. 일별잔고 탭의
  "계좌 관리"에서 계좌를 몇 개든 추가·삭제할 수 있고, 매매기록/일별잔고/대시보드/차트/CSV가 모두
  그 목록을 따라갑니다. 계좌를 삭제해도 이미 입력된 기록은 지워지지 않고 그대로 남습니다.
- **손절계획 탭 신설** — 별도로 쓰시던 손절계획 도구(종목별 기준가·5%/2.5%/8% 손절표·재매수
  계산기)를 탭으로 통합. 데이터는 `DB.losscut`에 저장되어 클라우드 동기화·백업에 함께 포함됩니다.
- **대시보드에 보유 종목 카드 추가** — 매매기록을 이동평균 원가법으로 계산해 계좌별로 어떤 종목을
  몇 주, 평균 얼마에 보유 중인지 보여줍니다(실시간 시세 연동은 없어 투자원금 기준입니다).
- **파일 기반 백업/복원** — 기존 텍스트 복사 방식에 더해 JSON 파일 다운로드/업로드 지원
  (구글 드라이브 동기화에 사용).
- **Firebase 실시간 클라우드 동기화(선택)** — 설정 시 Google 로그인만으로 여러 기기가 자동 동기화.
  설정하지 않으면 기존처럼 로컬 저장 + 수동 백업만 동작.
- **PWA 지원 + 즉시 업데이트** — `manifest.json` + `sw.js` 추가로 안드로이드/PC에 설치형 앱으로
  등록 가능. 서비스워커를 네트워크 우선 방식으로 바꿔, 온라인 상태로 앱을 열면 항상 최신 코드가
  반영되고 오프라인일 때만 캐시로 대체됩니다(설치된 앱도 자동 업데이트).
- CSV에 예수금 컬럼과 계좌목록 섹션 추가 (계좌 수가 가변적이라 헤더가 계좌 목록에 맞춰 자동 생성됨).

## 8) 아이콘 재생성

`icons/`의 PNG를 바꾸고 싶다면 `gen_icons.py`를 수정 후 아래처럼 실행하세요 (Pillow 필요).

```bash
python gen_icons.py
```
